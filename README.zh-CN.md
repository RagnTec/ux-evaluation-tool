### 在线体验

**[直接在浏览器中体验 UX Evaluation Tool →](https://ragntec.github.io/ux-evaluation-tool/)**

公开 Demo 可直接在浏览器中运行，无需本地安装，适合快速体验当前 v0.1 的评估流程。

UX Evaluation Tool 是一个开源、本地优先（Local-first）的 Web 评估工具，专为 UX 研究员、人因工程（Human Factors）专家、交互设计师及前端工程团队设计。它能够在设计图和界面截图阶段，针对多层人因工程基准、物理显示与交互测量、平台规范及无障碍标准，对视觉交互方案进行结构化风险评估与决策支持。

## 当前状态

**v0.1 Open Source Preview**

本项目目前为原型阶段的浏览器端工具，用于方法学与评估工作流探索。它展示了如何在进行正式可用性测试或软件开发之前，将物理显示环境、观看距离、物理交互尺寸及分层规则引入设计评审流程。

## 定位与应用场景

### 产品定位
* **设计图与截图级评估**：直接基于设计图或界面截图进行分析，无需依赖在线代码或复杂运行时环境。
* **人因工程与 UX 结合**：将物理显示参数（屏幕尺寸、分辨率、观看距离）与视觉感知、物理人机工效及交互尺寸相结合。
* **多层可解释规则模型**：在硬性基准（L1）、平台规范（L2）、人因理论模型（L3）、领域规则（L4）和自定义扩展层（L5）多层结构下进行评估。
* **情境化结果呈现**：结合当前结构化领域（Domain）、目标平台、观看距离与可用测量证据，解释规则适用性与风险依据。
* **空间证据标注**：将评估发现直接映射到图像归一化坐标系，提供可追溯的视觉与数据证据。

### 覆盖领域
* **移动端应用**（iOS / Android）
* **桌面与 Web 网页端**
* **车载 HMI 界面**（数字仪表盘、中控显示屏等）
* **通用 / 未指定**（在无特定领域门控时的默认领域回落，使用通用人因参考与物理测量基准）

---

## 边界与非目标声明

* **非通用 AI UI 生成器**：不自动生成 UI 界面或生成泛化文案。
* **非单一 WCAG 检查器**：无障碍（Accessibility）作为基础硬性层（L1），同时覆盖更广泛的人因工程、肢体运动控制及领域人机工效。
* **非可用性测试录屏平台**（如 Maze 或 UserTesting）。
* **非官方法规合规认证平台**：评估结果属于**设计决策支持与风险筛查工具**，不代表法律判断、行业强制合规证书或官方认证结论。
* **不可替代专业人因专家评审与真实用户研究**。

## 首次使用流程

1. **上传截图**：导入待评估的界面截图或设计方案（支持完整屏幕截图或保持 1:1 参考宽的局部裁切截图）。
2. **补充已知屏幕与评估上下文**：配置已知硬件参数（屏幕尺寸、分辨率、贴合模式）与评估上下文（使用领域、目标平台、典型观看距离）。
3. **可选补充设计尺寸基准**：若已知设计稿换算比例（pt / dp / CSS px），可填写设计宽度以解锁平台逻辑规则校验；**若无设计基准，直接保留未知即可**。
4. **圈选标注元素**：在画布上框选目标元素（文字、按钮、图标、输入框等），根据需要微调可视区域、触控热区或代表字符高度。
5. **查看风险、实际评估范围、使用参考与测量依据**：在检查侧边栏或报告预览中查看元素级风险、自动匹配的主要参考标准、已覆盖评估维度、待补充项与测量数据。

## 可配置输入与评估上下文

在当前 Public 版本中，用户可配置输入严格收口为 4 个结构化分类：

1. **截图与范围**：完整屏幕截图 / 局部裁切截图（支持保持 1:1 像素物理参考宽）。
2. **屏幕硬件参数**：屏幕对角线尺寸、硬件分辨率及包含 Letterbox 等比贴合假设的物理尺寸估算。
3. **评估上下文**：
   * **使用领域**：移动设备、桌面与 Web、车载界面、通用 / 未指定。
   * **目标平台**：Apple iOS、Google Android、Web 标准、自定义单位平台、未知 / 未指定。
   * **典型观看距离**：支持 mm、cm、m、inch 等单位解析。
4. **设计尺寸基准（可选）**：
   * **基准状态**：未提供设计尺寸（Unknown）、根据设备信息确定（Partial）、用户确认设计尺寸（Source Available）。
   * **逻辑换算**：设计单位（pt / dp / CSS px）与截图像素的比例关系。

### 目标平台与设计基准的完全解耦
目标平台与设计基准**完全独立**：
* **示例**：`使用领域 = 移动设备` + `目标平台 = Android` + `设计基准 = 未提供`。
  * 系统明确识别目标平台为 Android；
  * 依赖 `dp` / `sp` 的平台规则（如 Android 48×48 dp 触控目标）输出明确的 `needs_info`（待补充设计尺寸换算依据），不会导致元素整体失效；
  * 对比度检查（WCAG 2.2）、物理毫米尺寸、视距与视觉角、以及合格的人因降级参考（如 9 mm 触控目标、20′ 字符垂直视觉角）均保持正常运行。

### 结构化上下文边界说明
* 选择“车载界面”领域**不会**自动假定为驾驶员（Driver）角色或驾驶中（Driving）状态。
* 自由文本关键词（如“快速”、“移动中”）**不会**自动推断为紧急时间限制（Time-critical）。
* 细分驾驶员/乘客角色与具体操作姿态依赖未来结构化上下文输入支持。

## 自动评估范围与参考规范

系统**根据当前输入事实与测量证据自动匹配适用规则**，用户无需手动勾选规则族或评估维度。

### 实际评估范围（中性 Coverage 语义）
评估报告将实际涉及的维度清晰分区：
* **已覆盖评估维度**：采用实心圆点 **`●`** 呈现（如 `● 色彩对比`、`● 代表字符视觉角`、`● 物理触控目标`、`● 截图字号估算`）。
  > **注意**：覆盖范围仅代表该维度已执行有效计算或合理估算，**不等于全部通过（PASS）**。风险与通过结论仅在具体元素的 Finding / Rule Trace 中明确标识。
* **待补充后可评估**：采用空心圆 **`○`** 呈现（如 `○ Android 平台触控目标`、`○ Android 设计字号`），说明解锁平台规则所需的补充信息（无待补充项时自动隐藏）。

### 实际使用参考动态聚合
报告中展示的参考规范完全从本次真正参与比对的 Rule Trace 中提取：
* **主要比对参考**：真正产出已完成比对结论的权威标准与人因参考（如 `WCAG 2.2`、`Apple HIG`、`Android Accessibility`、`通用人因参考`）。
* **待解锁参考**：仅产出 `needs_info` 待补充提示的规范归入待解锁参考，不冒充已完成实测。

## 核心评估能力与精度模型

### 4 级评估精度模型
系统采用动态能力驱动策略（“知道什么填什么，系统自动使用最高可用精度”），无需全局强制模式切换，单个元素或检查项支持混合精度并行评估：

1. **截图事实（Screenshot Fact）**：基于图像像素尺寸、相对位置、屏幕占比及真实采样色彩计算。
2. **硬件参数估算（Hardware Assumed）**：结合屏幕对角线尺寸与物理分辨率，计算真实显示物理毫米（mm）尺寸。
3. **设计基准校验（Design Mapped）**：结合设计尺寸基准（pt / dp / CSS px 换算比例），执行平台官方交互规范校验。
4. **源数据确认（Source Confirmed）**：经人工或设计源文件确认的字号与热区参数，获得最高可信度结果。

### 无设计基准（No Design Basis）时的评估能力边界
当未提供设计尺寸基准（缺少 pt / dp / CSS px 比例映射）时，系统**不会将元素整体降级为无效**：

* **继续正常运行的评估项**：
  * **对比度评估**（WCAG 2.2 AA 文本 4.5:1 / 大文本 3:1 / 非文本 3:1）
  * **物理尺寸测量**（毫米尺寸与面积计算）
  * **观看距离与视觉角评估**（计算弧分 visual angle 并结合通用人因参考评估）
  * **人因参考降级评估（Human Factors Fallback References）**：
    * 字符高度垂直视觉角通用人因参考（基本参考 ≥ 16′，推荐参考 ≥ 20′）
    * 图形细节垂直视觉角通用人因参考（基本参考 ≥ 16′，推荐参考 ≥ 22′）
    * 物理触控目标尺寸推荐参考（通用手持直接触控 ≥ 9 mm）
    * *领域专项注记*：规则架构中已包含部分车载驾驶专项人因参考（如 NHTSA 驾驶员视角参考或 17.5 mm 驾驶触控参考），但当前 Public UI 尚未开放满足其角色 / 状态前置条件的结构化输入，因此这些专项参考默认不会作为直接适用规则激活。
  * **截图字号估算校验**（在可合理提取字符高度或单行文本高度时，提供估算字号参考）
* **仅在有设计基准时启用的评估项**：
  * 依赖平台逻辑单位（iOS pt、Android dp、Web CSS px）的官方交互规范校验（如 Apple HIG 44×44 pt、Android 48×48 dp 等）。

> **人因参考（Human Factors Reference）说明**：
> 人因参考（如 9 mm 物理触控尺寸、20′ 字符垂直视角）属于基于人体工效学与认知心理学研究的**决策参考基准**，不代表 Apple / Google 官方平台规范，亦不属于法规强制最低要求。

### 触控区域与文字尺寸边界
* **触控区域（Touch Bounds）**：基于物理尺寸（mm）或平台逻辑尺寸进行运动控制容错评估；**绝不通过观看距离或视觉角缩放触控规则**。
* **文字尺寸模型**：
  * **设计源字号（Source Font Size）**：最高优先级，经设计源确认。
  * **截图字号估算（Screenshot Font Size Estimate）**：由像素或字符高度换算，明确标记为估算校验，不冒充设计源事实。
  * **代表字符高度测量（Character Height Measurement）**：提取真实渲染字符高度，支撑视觉角与人因可读性评估。

## 快速上手

### 环境要求
* [Node.js](https://nodejs.org/)（推荐 18.0.0 或更高版本）
* npm（随 Node.js 一同提供）

### 本地安装与运行

```bash
# 克隆仓库
git clone https://github.com/RagnTec/ux-evaluation-tool.git
cd ux-evaluation-tool

# 安装依赖
npm install

# 运行自动化测试
npm test

# 启动本地开发服务器
npm run dev

# 构建生产版本
npm run build
```

启动后在浏览器打开 `http://localhost:5173` 即可进入本地评估工作区。

## 评估方法与分层模型

```
┌─────────────────────────────────────────────────────────┐
│ L1: 硬性约束（声明的规范基线，如 WCAG 2.2 AA）          │
├─────────────────────────────────────────────────────────┤
│ L2: 平台规范（Apple HIG、Material Design 等）           │
├─────────────────────────────────────────────────────────┤
│ L3: 人因理论与模型（视觉感知与运动控制模型）            │
├─────────────────────────────────────────────────────────┤
│ L4: 领域规则（车载 HMI 及领域规范）                     │
├─────────────────────────────────────────────────────────┤
│ L5: 自定义扩展层（架构扩展点）                          │
└─────────────────────────────────────────────────────────┘
```
> *注：当前 Public UI 聚焦于 L1–L4 评估链路，暂未开放自定义规则编写（L5）。*

### 证据与置信度分级
评估结论严格标注证据来源与依据状态：
* `verified_reference`：已核实标准的正式参考。
* `example_reference`：演示性或研究型示例参考。
* `pending_verification`：待补充源数据核验的推断结果。

## 当前局限性

* **无全图自动 CV / OCR**：采用人工圈选与测量，避免 speculative 计算机视觉误判。
* **不从截图自动推断设备密度**：逻辑单位换算仅基于用户确认的设计尺寸，或明确选择且具备可信映射的设备 Profile；不会仅凭截图像素自动猜测 pt / dp / CSS px 比例。
* **本地浏览器存储**：数据基于浏览器 IndexedDB 本地保存，无云端同步，清理站点数据将重置工作区。
* **无端到端浏览器自动化套件**：核心算法、人因模型与状态流转均由自动化单测覆盖（`npm test`），UI 端到端视效主要基于本地手工交互验证。

## 隐私与数据安全
