# 08 解释层与呈现架构设计

[English](./08_explanation_layer_design.md) | **简体中文**

---

## 1. 定位与呈现层架构职责

**解释层（Explanation Layer）**负责将底层的原始空间测量数据、硬件校准参数以及规则追溯记录（`RuleComparisonTrace`）转化为结构化、易于人脑理解的行动建议。

作为纯粹的呈现转换层（`src/utils/elementPresentation.ts`、`src/utils/reportGenerator.ts`），解释层将数值比对结果映射为对设计师友好的反馈卡片，自身不执行原始物理推导，亦不改变工作区的底层持久化状态。

---

## 2. 核心解释职责与信息模型

在检查器抽屉（Inspector Drawer）与导出报告中，每个元素的评估结论均履行九项核心沟通职责：

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 当前测量结果 (Current Measurement) │ 格式化数值、单位、限制轴维度   │
│ 2. 判定结论 (Verdict & Status)        │ 达到参考、未达推荐、需关注等   │
│ 3. 规范引用 (Rule Citation)           │ 标准标题、规则 ID、所属层级    │
│ 4. 数值比对详情 (Comparison Detail)   │ 阈值差值、余量/缺口、限制轴    │
│ 5. 现行假设 (Active Assumptions)      │ 校准 PPI、设计基准比例、字号估算│
│ 6. 待补全信息 (Missing Inputs)        │ 解锁更高精度所需的具体缺失参数 │
│ 7. 机制原理 (Why It Matters)          │ 视觉感知、肢体工效或认知影响   │
│ 8. 改进行动建议 (Recommendation)      │ 明确、可落地的设计优化建议     │
│ 9. 认识论来源 (Epistemic Provenance)  │ 精度等级、证据状态、论断强度   │
└────────────────────────────────────────────────────────────────────────┘
```

### 详细字段解析：
- **当前测量结果（`currentValueDisplay`, `unit`）**：格式化后的物理或逻辑尺寸（如 `52 × 40 dp`、`1.16:1`、`18.4'`）。
- **判定结论（`verdict`, `verdictLabel`）**：标准化的结论标识（`meets` 达到推荐范围、`below_recommended` 未达推荐、`attention` 需关注、`estimated_meets` 估算达标、`needs_info` 待补充信息等）。
- **规范引用（`ruleTitle`, `ruleId`, `ruleLayer`）**：正式的标准或指南条款（如 `WCAG 2.2 SC 1.4.3`、`Apple HIG`、`通用人因参考`）。
- **数值比对详情（`comparison`）**：清晰展示目标阈值与余量（如 `余量 +4 dp` 或 `距离参考还差 8 dp`）。
- **现行假设（`assumptions`）**：明确告知的背景前置条件（如“基于标称 500 mm 视距”、“基于单行文字高度估算”）。
- **待补全信息（`missingInputs`）**：明确指出解锁更深层次评估所需的缺失项（如“缺少屏幕对角线参数，无法换算物理毫米”）。
- **机制原理（`whyItMatters`）**：解释该项人机工效指标的实际体验影响（如为什么触控热区间距不足会导致误触）。
- **改进行动建议（`recommendation`）**：向设计师或研发人员提供的具体调整策略（如“建议将触控热区外边距扩展至至少 48 × 48 dp”）。
- **认识论来源（`evaluationTier`, `evidenceStatus`, `claimStrength`）**：告知结论是直接标准命中、理论推导还是启发式估算。

## 3. 评估覆盖度与评估结论的严格区分

解释层坚守认知清晰与认识论诚实原则：

### 3.1 覆盖度不等于通过（Coverage ≠ PASS）
- **评估覆盖度（Evaluated Coverage）**：指具备完整证据并成功执行规则检测的元素比例。
- **结论分布（Verdict Distribution）**：各项规则实际的判定结果分布（达标、需关注、未达推荐等）。
- *严格规则*：高覆盖度仅代表系统成功对各元素执行了可用的规则比对，**绝不可**被表述为“测试通过（Pass）”。

### 3.2 区分活跃规则与待解锁规则
- **活跃规则（Active References）**：当前在已有证据下正在生效并给出判定的规则。
- **待解锁规则（Unlockable References）**：处于 `needs_info` 状态的规则，当用户补充上下文输入（如提供设计基准比例解锁平台字号规则、提供屏幕对角线解锁物理触控毫米规则）后自动激活。

## 4. UI 交互与导出报告呈现体系

### 4.1 元素检查抽屉面板（`src/components/ElementInspectorDrawer.tsx`）
用户在画布中选定任一标注元素时：
- **顶部摘要**：元素名称、语义类型（按钮、文字、图标）及精度等级徽章（Precision Tier）。
- **多维度物理与空间卡片**：展示渲染像素、校准物理毫米与人眼视角弧分。
- **规则比对卡片**：以清晰的语义状态标签展示比对详情、余量分析、机制原因与行动建议。
- **上下文与门控提示**：展示参数缺失警告与领域适用性说明。

### 4.2 单文件自包含导出报告（`src/utils/reportGenerator.ts`）
- 生成零外部依赖的独立 HTML 报告文件。
- 内置概要看板、适用规则清单、各元素详细比对表以及 Base64 编码的 Canvas 画布证据截图。

---

## 5. 决策支持定位与合规声明

为维护技术与法律严谨性：
- 所有卡片结论、操作提示与导出报告均定位于**前期设计决策支持参考**，旨在帮助团队在代码实现前尽早识别工效风险。
- 解释层在文案中明确避免做出法定或强制性合规认证声明。
