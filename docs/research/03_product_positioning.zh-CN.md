# 03 研究定位与产品定位分析

[English](./03_product_positioning.md) | **简体中文**

---

## 1. 概述与研究定位

**UX Evaluation Tool** 是一个开源、本地优先（Local-first）的研究与评估工具，专注于在**设计图与界面截图级别**对用户界面方案进行人机工效学与 UX 风险评估。

它为产品经理、交互/视觉设计师、用户研究员及人因工程师提供了一个结构化的浏览器端工作区，用于将界面空间与视觉证据置于物理显示几何、平台官方规范及人因工程研究基准下进行定量核验与风险发现。

---

## 2. 行业三方断层与产品存在价值

在早期设计迭代、设计评审及开发前交付阶段，数字化产品团队普遍面临三方工具断层：

```
┌────────────────────────────────────────────────────────────────────────┐
│                          现存工具生态与局限                            │
├──────────────────────────┬─────────────────────────┬───────────────────┤
│ 1. 纯代码无障碍检测工具 │ 2. 实证可用性测试平台   │ 3. 重型人因仿真软件│
│ (Axe, Lighthouse, Wave)  │ (Maze, UserTesting)     │ (3D CAD, 光学实验)│
├──────────────────────────┼─────────────────────────┼───────────────────┤
│ • 必须依赖运行态 DOM 结构│ • 介入节点靠后（需工程）│ • 门槛与学习成本极高│
│ • 无法感知物理显示毫米   │ • 周期长、成本高昂      │ • 仅支持 3D CAD 模型│
│ • 无法用于静态设计图评审│ • 侧重交互行为漏斗      │ • 脱离日常敏捷设计│
└──────────────────────────┴─────────────────────────┴───────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   UX Evaluation Tool (设计图人因桥梁)                  │
│  • 无需工程代码，直接在设计图与界面截屏上执行空间证据评估              │
│  • 物理显示几何换算与双轴硬件校准（mm/px）                             │
│  • 分层可追溯规则体系（L1 硬性底线、L2 平台规范、L3 人机工效）          │
│  • 100% 浏览器本地运行，数据隐私绝对安全                               │
└────────────────────────────────────────────────────────────────────────┘
```

1. **依赖代码的 Web 无障碍检查器（Axe、Lighthouse）**：必须依赖运行态 HTML/DOM 结构，无法直接对静态设计草图、车机中控效果图或嵌入式硬件界面截屏进行前期校验。
2. **实证可用性测试平台（Maze、UserTesting）**：通常需要可交互的工程原型，当在测试中发现触控偏小或文字辨识困难等基础人因缺陷时，方案返工成本高昂。
3. **重型人机工效与实验室仿真软件（RAMSIS、CATIA 人因模块）**：依赖复杂的 3D CAD 建模与光学实验室设备，难以满足普通数字化产品团队在日常敏捷设计中的轻量化评估需求。

UX Evaluation Tool 填补了这一空白，将**确定性人因工程计算、平台交互规范及空间证据标注**直接带入浏览器端的设计图评审工作流中。

## 3. 明确的边界与非目标（What We Are Not）

为确保产品范围与预期的清晰度：
- **不是宽泛的生成式 AI UI 审查工具**：不依赖未经事实锚定的大语言模型（LLM）视觉直觉或黑盒 AI 评分。所有评估逻辑均为确定性、基于规则且可追溯至具体标准。
- **不是全自动计算机视觉（CV）或 OCR 工具**：不依靠算法猜测界面元素边界或屏幕像素密度。所有空间证据均建立在用户明确框选的空间范围及显式硬件/设计参数基准之上。
- **不是单纯的 WCAG 检查器**：虽然内置 WCAG 色彩对比度评估，但其核心是将无障碍规则作为更广泛人因与交互几何评估框架中的基础组成部分。
- **不是可用性测试平台**：不替代基于真实用户的实证可用性测试、眼动仪实验或行为数据分析平台。
- **不是法律合规认证系统**：评估结论与导出报告仅作为**前期风险发现与设计决策支持参考**，不构成法定或强制性合规认证背书。
- **不是云端 SaaS 协作平台**：100% 运行于用户本地浏览器环境中，采用本地 IndexedDB（`ux_evaluation_workspace_db`）进行持久化，无任何外部数据上传或网络回传。

## 4. 目标用户群体与研究画像

- **交互设计师与产品设计师**：在设计定稿或研发交付前，核验物理触控区域、按键间距防误触及排版可读性。
- **人因工程师与工效学专家**：针对车载中控、智能座舱仪表盘、工业触控屏或医疗设备界面，进行视距角度及物理尺寸基准评估。
- **用户研究员**：在启发式评估（Heuristic Evaluation）或专家走查中，收集结构化、量化的空间数据证据。
- **产品经理**：在早期方案阶段评估界面可行性、多端屏幕适配风险及无障碍基础体验。
- **智能座舱 HMI 与嵌入式设备团队**：在代码实现前针对车载屏幕、家电触控面板及 IoT 设备屏幕进行界面人因走查。

---

## 5. 首阶段核心场景领域

1. **移动端与手持设备界面**：直接触控人机工效（对应通用手持直接触控参考 ≥ 9 mm）、平台规范（Apple HIG 44 pt、Android Material 48 dp）及手持视距几何。
2. **智能座舱中控屏与仪表界面**：座舱视距几何与显示包络（在未提供结构化上下文时不预设驾驶分心或行车动态法规）。
3. **桌面与 Web 网页界面**：光标与触控目标尺寸（WCAG 2.2 SC 2.5.8）、显示器视距几何及文字排版层级。
4. **智能家电与嵌入式触控面板**：物理显示屏直接触控接触面积与图形细节辨识。

---

## 6. 核心差异化价值

核心差异化在于融合了 **人机工效理论 + 平台设计规范 + 可解释规则追溯链**：
- **分层确定性规则体系**：在硬性底线（L1）、平台规范（L2）、人因理论模型（L3）和领域规则（L4）等多层结构下，生成透明、可核验的规则比对追溯链（Rule Trace）。
- **能力与证据驱动的精度分级**：根据当前可用的测量证据自动应用最高精度等级（4-Tier Precision Model：截图事实、硬件假定、设计映射、设计源确认）。
- **坚守认识论诚实**：严格区分直接标准命中（`rule_match`）、工效理论推导（`theory_inference`）以及启发式风险信号（`heuristic_risk`）。
