# 规则跨视距与跨场景可移植性审计

[English](./rule_transferability_audit.md) | **简体中文**

---

## 1. 概述与核心科学问题

在 Phase 3K.0 建立纯人因工程计算核心、Phase 3K.1 接入视角测量能力后，本审计（**Phase 3K.2A**）系统评估了现有及未来的规则类别在科学层面是否支持跨场景适配（例如：将移动端推荐规范移植至桌面大屏或车载座舱显示器）。

### 核心科学问题
规则可移植性的核心审判标准**不是**：
> *“是否可以在数学上把尺寸阈值直接乘以视距比例？”*

真正的科学审判标准是：
> **“保持视角一致（θ = 2 arctan(size / (2 · distance))），是否能够真实保护原始规则所旨在保护的人体生物/认知机制？”**

### 审计结论
- **本阶段不修改、不缩放任何生产级规则阈值。**
- **生产级规则中归属于 `visual_angle_equivalent`（视角等效可移植）的数量为零。**
- 所有现行生产规则严格保持分类为 `direct_only`（仅直接适用）或 `unknown`。

## 2. 审计方法与人因机制分类

为杜绝错误的跨域阈值缩放，每项规则必须拆解至其底层的生物力学或认知感知机制：

| 机制类别 | 生物力学 / 感知心理学基础 | 典型规则示例 |
| :--- | :--- | :--- |
| `motor_target_acquisition` | 肢体运动目标捕获、菲茨定律、手眼协调、指腹接触面积 | 触控目标尺寸（44 pt、48 dp、24 × 24 CSS px） |
| `motor_error_prevention` | 运动控制抖动、肢体震颤、车辆震动、防误触间隙 | 触控间距、热区重叠互斥约束 |
| `visual_legibility` | 视网膜空间分辨率、字符笔画辨识、视觉敏度 | 字体字号、字形 x-height、字符可读性 |
| `visual_recognition` | 轮廓识别、图标语义解析、视觉显著性 | 图标尺寸、角标可见性 |
| `visual_discrimination` | 感光细胞亮度对比敏感度（CSF）、边缘检测 | 文本对比度（4.5:1）、非文本对比度（3.0:1） |
| `layout_density` | 视觉拥挤、周边视觉干扰、认知扫描负荷 | 信息密度、留白边距 |
| `platform_convention` | 生态设计语言规范、品牌一致性、系统级工效习惯 | 平台特定 UI 组件与排版层级 |
| `accessibility_requirement` | 法定无障碍合规基准（如 WCAG Level AA 成功准则） | WCAG 2.2 准则 |
| `unknown` | 未分类、复合型或未核验的启发式检测 | 通用启发式建议 |

## 4. 机制类别审计总结

### 4.1 触控目标尺寸与间距（肢体交互）
- **保护机制**：`motor_target_acquisition` 与 `motor_error_prevention`。
- **审计结论**：触控目标规则服务于肢体运动控制及按压精准度，受交互介质、手指物理尺寸、姿态与震动影响。
- **科学推论**：当视距变化时，人手解剖结构与手指接触面绝不会随视距成比例变化。若仅按视角换算触控目标尺寸，将严重混淆视觉发现与肢体触控工效。
- **治理策略**：**严格定义为 `direct_only`（不可按视角移植）**。

### 4.2 色彩对比度（光度辨别）
- **保护机制**：`visual_discrimination`。
- **审计结论**：对比度是相对亮度的无量纲比值（(L1 + 0.05) / (L2 + 0.05)）。虽然人眼对比敏感度函数（CSF）随空间频率变化，但标准条款本身（4.5:1）是绝对光度指标。
- **治理策略**：**严格定义为 `direct_only`**，不接受任何视距乘数换算。

### 4.3 文字字号与排版（视觉可读性）
- **保护机制**：`visual_legibility`。
- **审计结论**：文字可读性取决于字形笔画宽度、x-height 及文字复杂度，而非文本容器框的整体外尺寸。
- **证据缺失**：
  1. 平台指南（iOS HIG、Material Design）以点（`pt`）或独立像素（`sp`）定义字号，但未在官方文本中给出权威的标称视距。
  2. 截图上的矩形框包含字偶上下行距空白。
- **治理策略**：**`insufficient_evidence`（证据不足）**。在缺乏单字字形笔画与标称视距出处时，不可将字号规则换算为视角门槛。

### 4.4 图形符号与图标辨识（视觉目标）
- **保护机制**：`visual_recognition`。
- **审计结论**：针对非交互的图形符号（如状态图标、警示标志），视网膜视角直接决定辨识概率。
- **治理策略**：**`candidate_for_visual_angle_review`（仅作为候选审计状态）**。
- **前置条件**：在具备经过验证的完整人因参考上下文前，不直接在生产环境激活。

## 5. 未来视角等效移植的最低证据要求

任何规则从 `insufficient_evidence` 升级至 `visual_angle_equivalent` 必须满足以下 **9 项最低证据条件**：

1. **可溯源的原始标准**：明确的标准规范出处（如 ISO 9241-303、ISO 15008、MIL-STD-1472H）。
2. **支持的人因机制**：确认为保护视觉辨识或字符可读性（非肢体触控）。
3. **基准物理测量指标**：以物理毫米或校准笔画宽度定义（非抽象点单位）。
4. **权威的参考视距**：官方规范中明确载明的标称视距（非推测或假定）。
5. **目标视距数据**：用户核验或空间推导的目标视距。
6. **目标物理显示映射**：经过有效硬件校准的屏幕参数。
7. **无不兼容的混淆机制**：目标元素为非交互图形，或具有独立的触控评估。
8. **显式假设追溯**：环境假设（扫视时长、车身震动、环境光）完整记录。
9. **证据强度 ≥ Verified**：具备正式人机工效学文献支持。

## 6. 证据链分层治理

在评估跨场景适配阈值时，多个独立来源绝不可混淆：

```
[规则标准出处]     -> 定义标称阈值与设计保护机制
[参考视距出处]     -> 人因文献 / 实证研究
[目标硬件参数]     -> 目标屏幕 DPI 与对角线尺寸
[使用上下文证据]   -> 观察者实际视距与坐姿
```

每个环节保持独立的 `provenance`（出处记录）与 `evidence_level`（证据等级）。

## 7. 语义区分：直接规则 vs 上下文适配参考

| 维度 | 直接规则 (`rule_match`) | 上下文适配参考 (`theory_inference`) |
| :--- | :--- | :--- |
| **性质** | 针对适用标准阈值的直接核验 | 投射至不同使用上下文的科学估算 |
| **论断强度** | 正式约束 (`L1` / `L2`) | 信息推断 (`L3`) |
| **判定标签** | 达标 (Meets) / 需关注 (Attention) / 不达标 | 人因参考视角 (Contextual Reference Only) |
| **合规声明** | 可声明标准符合性（如 WCAG 2.2 AA） | **绝不可声明符合或违反原始标准** |

## 8. 待准入的外部证据线索

### 8.1 W3C CSS Reference Pixel
- **来源规范**：W3C CSS Values and Units Module。
- **标准定义**：参考像素基于视角定义（96 DPI 设备在一臂之长视距下 1 像素张开的视角，标称约 0.0213 度 / 1.28 弧分）。
- **潜在意义**：为理解 CSS 视觉单位几何缩放提供权威依据。
- **关键边界**：该定义**不代表** WCAG SC 2.5.8（目标尺寸 24 × 24 CSS px）可按视角换算，因为 SC 2.5.8 保护的是肢体触控。

### 8.2 Apple 官方平台指南
- **来源规范**：Apple Human Interface Guidelines。
- **定义**：原生点单位排版表（Dynamic Type）与 44 × 44 pt 推荐触控目标。
- **关键边界**：官方平台的数值指南本身**不提供**跨场景视角换算所需的标称视距或字符笔画度量。

## 9. 来源核验与可移植性资格的双轴分离

评估模型严格区分两个独立的评价维度：

1. **`source_rule_verified`（来源是否核验）**：规则原始阈值是否对照官方规范完成逐字核验。
2. **`transferability_qualified`（是否具备移植资格）**：规则是否具备必要的机制、物理度量及标称视距，以支持跨上下文适配。

一条规则可以具备**官方已核验来源**，同时严格保持为 **`direct_only`**（仅直接适用）或 **`insufficient_evidence`**（移植证据不足）。
