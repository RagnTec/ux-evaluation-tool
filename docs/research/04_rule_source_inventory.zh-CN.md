# 04 规则来源清单与证据分类治理

[English](./04_rule_source_inventory.md) | **简体中文**

---

## 1. 概述与清单治理目标

本文档系统梳理了 **UX Evaluation Tool** 所调研与核验的正式标准、平台官方规范、人机工效学理论模型及行业领域依据。

为坚守认识论诚实（Epistemic Honesty）并防止过度断言，清单中的所有来源均被赋予明确的运行状态分级：
1. **运行时依据（Runtime Reference）**：在满足适用条件时参与当前确定性评估流程。
2. **L4 领域适用性支持（Domain-Aware Support）**：已具备领域专项参考与适用性控制逻辑，但实际激活取决于匹配的结构化场景条件。当前 Public UI 尚未开放部分车载专项参考所需的完整角色 / 状态输入。
3. **调研合格依据（Research-Qualified Reference）**：已完成证据来源与作用机制的资格判断，但不会因此自动参与运行时评估。实际进入比对还需要满足测量目标、场景适用性，并存在对应的已实现评估路径。
4. **待核验依据（Pending-Verification）**：处于学术调研或待复核阶段的候选基准，未经独立核验的具体条款不作为生产级强制依据。
5. **架构预留扩展（Architectural Extension）**：数据模型中已定义相关接口与结构，面向用户的编辑与录入界面将在后续版本中逐步开放。

## 2. 多层规则来源全景清单

```
┌────────────────────────────────────────────────────────────────────────┐
│ L5: 自定义规则层 (Custom Rules，架构预留扩展层)                        │
├────────────────────────────────────────────────────────────────────────┤
│ L4: 行业与领域规则 (Domain Rules，车载 HMI、桌面 Web、嵌入式设备)       │
├────────────────────────────────────────────────────────────────────────┤
│ L3: 人因工程模型 (Human Factors，视距视角、9 mm 触控等)                │
├────────────────────────────────────────────────────────────────────────┤
│ L2: 平台官方规范 (Platform Guidelines，Apple HIG、Android Material)    │
├────────────────────────────────────────────────────────────────────────┤
│ L1: 底层硬性基准 (Hard Constraints，WCAG 2.2 AA、空间热区重叠冲突)     │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.1 L1 — 底层硬性基准与正式标准（Hard Constraints）

| 标准规范名称 | 审计条款 / 议题 | 运行状态 | 论断强度 | 保护机制 |
| :--- | :--- | :--- | :--- | :--- |
| **WCAG 2.2 SC 1.4.3** | 文本对比度最低要求（普通文本 4.5:1，大文本 3.0:1） | **运行时已接入** | `strong` | `visual_discrimination` |
| **WCAG 2.2 SC 1.4.11** | 非文本对比度（界面组件与图形图标 3.0:1） | **运行时已接入** | `strong` | `visual_discrimination` |
| **WCAG 2.2 SC 2.5.8** | 目标尺寸最低要求（Web 交互目标 24 × 24 CSS px） | **运行时已接入** | `strong` | `motor_target_acquisition` |
| **空间几何检测** | 触控热区重叠与点击歧义检测 | **运行时已接入** | `strong` | `motor_error_prevention` |
| **EN 301 549 / Section 508** | 公共部门数字无障碍标准族对齐 | 调研参考 | `moderate` | `accessibility_requirement` |

*治理边界*：L1 硬性约束具有最高优先级，平台规范或自定义规则不可静默覆盖 L1 缺陷。

### 2.2 L2 — 平台官方规范与交互设计指南（Platform Guidelines）

| 规范来源 | 审计建议条款 | 运行状态 | 论断强度 | 保护机制 |
| :--- | :--- | :--- | :--- | :--- |
| **Apple HIG（触控尺寸）** | 44 × 44 pt 推荐触控尺寸 | **运行时已接入** | `strong`（平台规范） | `motor_target_acquisition` |
| **Apple HIG（文字排版）** | 17 pt 正文字号推荐（11 pt 最低要求） | **运行时已接入** | `strong`（平台规范） | `visual_legibility` |
| **Android Material（触控）**| 48 × 48 dp 推荐触控尺寸 | **运行时已接入** | `strong`（平台规范） | `motor_target_acquisition` |
| **Android Material（字号）**| 16 sp 正文字号推荐（12 sp 最低要求） | **运行时已接入** | `strong`（平台规范） | `visual_legibility` |
| **Microsoft Fluent** | 桌面端光标与触控交互适配指南 | 调研参考 | `moderate` | `platform_convention` |

*治理边界*：平台规范代表生态厂商的最佳实践，依赖明确的设计基准比例（pt/dp 换算）。未声明设计基准时输出 `needs_info`，不阻塞物理与对比度计算。

| 模型 / 来源依据 | 评估基准阈值 | 运行状态 | 论断强度 | 保护机制 |
| :--- | :--- | :--- | :--- | :--- |
| **视网膜视角分辨模型** | 代表字符垂直视角（基本参考 ≥ 16′，推荐参考 ≥ 20′） | **运行时已接入** | `moderate`（实证模型） | `visual_legibility` |
| **图形细节辨识模型** | 图标细节垂直视角（基本参考 ≥ 16′，推荐参考 ≥ 22′） | **运行时已接入** | `moderate`（实证模型） | `visual_recognition` |
| **生物力学触控工效学** | 通用手持直接触控物理参考（边长 ≥ 9 mm） | **运行时已接入** | `moderate`（生物力学） | `motor_target_acquisition` |

### 2.4 L4 — 行业领域与特定场景规则（Domain Rules）

| 领域来源 | 适用范围与说明 | 运行状态 | 论断强度 | 保护机制 |
| :--- | :--- | :--- | :--- | :--- |
| **座舱显示器视距几何** | 车载中控屏与仪表屏标称视距包络 | **领域适用性支持**（场景门控） | `moderate` | `visual_legibility` |
| **NHTSA DOT HS 812 360** | 驾驶员界面设计指南（文字与图标视角建议） | 调研合格 | `moderate`（建议） | `visual_legibility` / `visual_recognition` |
| **ISO 15008:2017** | 车载视觉显示工效规范与测试程序 | 待核验依据（具体条款） | 描述性 | `visual_legibility` |

*治理边界*：在当前 Public 版本中选择车载领域仅确立座舱视距几何，并不等同于驾驶分心或行车动态法规，后者需依赖具体的驾驶员角色与行车动态上下文输入。

---

### 2.5 L5 — 自定义规则层（Architectural Extension）

- **来源类型**：用户或企业自定义的设计规范、品牌指南及定制项目验收标准。
- **运行状态**：**架构预留扩展层**（数据结构已在模型中定义，规则编辑与管理 UI 暂未在 Public v0.1 开放）。
- **治理规则**：自定义规则可增加更严格的要求或特定业务校验，但不可静默覆盖或消除 L1 底层硬性基准。

## 3. 认识论推理类型输出分类

系统生成的每条规则追溯记录均包含确定的推理类型标记：
- **`rule_match`**：直接命中已核验的标准条款或平台官方规范。
- **`theory_inference`**：基于人机工效学或感知认知理论模型的数学推导。
- **`heuristic_risk`**：基于估算测量或布局密度的启发式风险信号。
- **`custom_rule`**：命中用户配置的自定义规则。

## 4. 证据治理核心原则小结

1. **平台指南不等于法律法规**：Apple HIG 与 Material Design 属于平台生态的最佳实践建议，非强制性法律指令。
2. **人因模型不等于合规底线**：人因视角参考（≥ 16′/20′）代表实证工效学推荐，非强制法定门槛。
3. **触控规则不可按视角换算**：物理触控（≥ 9 mm）取决于手指物理肉垫接触面与肢体运动控制，绝不可换算为视角弧分。
4. **覆盖度不等于通过（Coverage ≠ PASS）**：高评估覆盖度仅代表元素已完成可用规则的客观比对，绝不代表“全项通过”。
