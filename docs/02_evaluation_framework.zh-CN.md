# 02 评估框架与多层规则体系

[English](./02_evaluation_framework.md) | **简体中文**

---

## 1. 评估框架定位与设计哲学

**UX Evaluation Tool** 的评估框架旨在为设计图阶段的用户界面方案提供**多层次、可解释且可追溯的风险评估**。

与单一的无障碍校验脚本或黑盒视觉 AI 评论不同，本框架：
- 将界面风险拆解至清晰的**分层规则模型（L1–L5）**（从底层无障碍硬性基准到高层人机工效模型）。
- 严格区分**人类感知/生物运动控制机制**（如视网膜视角分辨率、肢体触控按压精度）与单纯的像素比例换算。
- 坚守**认识论诚实（Epistemic Honesty）**：清晰区分设计源事实、物理硬件换算、启发式估算及待补充解锁项。

---

## 2. 多层规则体系架构（L1–L5）

L1–L3 已包含当前 Public 版本中直接开放的评估路径；L4 提供领域适用性控制与领域专项规则支持，其实际激活取决于当前可用的结构化场景条件；L5 在当前 Public 版本中仍属于架构扩展层。

```
┌───────────────────────────────────────────────────────────┐
│ L5: 自定义规则层 (Custom Rules，架构预留扩展层)            │
├───────────────────────────────────────────────────────────┤
│ L4: 行业与领域规则 (Domain Rules，车载 HMI、桌面 Web、通用) │
├───────────────────────────────────────────────────────────┤
│ L3: 人因工程模型 (Human Factors，视距视角、9mm 触控等)     │
├───────────────────────────────────────────────────────────┤
│ L2: 平台官方规范 (Platform Guidelines，Apple HIG、Material)│
├───────────────────────────────────────────────────────────┤
│ L1: 底层硬性基准 (Hard Constraints，WCAG 2.2 AA、热区重叠) │
└───────────────────────────────────────────────────────────┘
```

### L1 — 底层硬性基准（Hard Constraints）
- **范围**：通用的无障碍合规底线及物理几何互斥约束。
- **v0.1 已接入标准**：
  - `L1-WCAG-SC-1.4.3`：文本对比度最低要求（普通文本 4.5:1，大文本 3.0:1）。
  - `L1-WCAG-SC-1.4.11`：非文本对比度最低要求（界面组件与图形图标 3.0:1）。
  - `L1-WCAG-SC-2.5.8`：目标尺寸最低要求（Web 交互目标 $24 \times 24\text{ CSS px}$）。
  - `touch_overlap_conflict`：空间几何检测，标记相邻触控热区的重叠冲突。
- **认识论类型**：`rule_match`（命中规则）。硬性基准优先级最高，不可被下层规范静默覆盖。

### L2 — 平台官方规范（Platform Guidelines）
- **范围**：各主流操作系统与设计生态官方发布的交互设计指南与排版规范。
- **v0.1 已接入规范**：
  - **Apple HIG**：$44 \times 44\text{ pt}$ 触控目标推荐；$17\text{ pt}$ 正文字号推荐（$11\text{ pt}$ 最低要求）。
  - **Android Material / 无障碍**：$48 \times 48\text{ dp}$ 触控目标推荐；$16\text{ sp}$ 正文字号推荐（$12\text{ sp}$ 最低要求）。
- **认识论类型**：`rule_match`（在具备已确认或已映射的设计单位时执行）。

### L3 — 人因工程与认知模型（Human Factors）
- **范围**：基于生物力学、视觉感知工效学及认知心理学研究的量化模型。
- **v0.1 已接入基准**：
  - **代表字符垂直视角**：$\theta = 2 \arctan(h / 2D)$，基于通用人因参考评估（基本参考 $\ge 16'$，推荐参考 $\ge 20'$）。
  - **图形细节垂直视角**：基于图标辨识人因参考评估（基本参考 $\ge 16'$，推荐参考 $\ge 22'$）。
  - **通用手持直接触控物理参考**：基于人体手指接触工效学基准评估（$\ge 9.0\text{ mm}$ 直接触控边长）。
- **认识论类型**：`theory_inference`（理论推断）或 `heuristic_risk`（启发式风险）。人因模型代表经验设计参考，非强制法规。

### L4 — 行业与领域规则（Domain Rules）
- **范围**：针对特定交互环境、设备类型与任务关键性的领域规则门控。L4 规则的实际激活取决于当前可用的结构化场景条件。
- **v0.1 适用性门控**：
  - **车载 HMI（Automotive）**：基于座舱视距环境筛选适用的视角包络。注意：选择车载领域并不自动等同于驾驶员角色、行车动态或时间紧迫任务；车载专项基准需结合适用的结构化上下文，当前 Public UI 尚未开放全部座舱角色与行车状态输入。
  - **桌面与 Web 网页（Desktop / Web）**：应用显示器视距几何与指针/触控交互基准。
  - **通用 / 未指定（General）**：默认回落领域，应用通用人因与物理测量基准。
- **认识论类型**：`domain_adapted`（领域适配）。

### L5 — 自定义扩展层（Custom Rules，架构预留）
- **范围**：企业内部设计规范、特定品牌规则或定制项目验收标准。
- **v0.1 状态**：数据模型已定义；自定义规则录入与管理 UI 暂未在 v0.1 开放。

## 3. 认识论推理类型（Epistemic Reasoning Types）

系统中的每个规则判定（Rule Trace）均明确标明其推理依据类型：

| 推理类型 | 认识论基础 | 输出标识（中 / 英） |
| :--- | :--- | :--- |
| `rule_match` | 明确映射至已核验的标准条款或平台官方指南 | 命中规则 / Rule Match |
| `theory_inference` | 基于感知或工效学模型的数学物理推导 | 理论推断 / Theory Inference |
| `heuristic_risk` | 基于估算测量或布局密度的启发式风险信号 | 启发式风险 / Heuristic Risk |
| `custom_rule` | 源自用户配置的自定义规则 | 自定义规则 / Custom Rule |

## 4. 规则适用性与评估结论语义

### 动态适用性匹配
评估引擎**根据当前输入事实与测量证据自动匹配适用规则**（元素类型、交互类型、目标平台、设计基准、视距等），用户无需手动勾选规则族。

### 判定结论分类
针对适用规则，系统产出明确的结论状态：
- `meets_reference`：达到或优于推荐及规范阈值（通过 PASS）。
- `below_recommended`：达到基本最低要求但低于推荐值（建议性风险）。
- `below_threshold`：低于最低要求或违反非重叠约束（高风险）。
- `needs_info`：规则适用，但需要补充必要参数（如视距或设计基准）方可完成完整计算。

### 中性评估覆盖范围语义（Coverage Semantics）
在报告与预览中，维度覆盖被清晰分区：
- **已覆盖评估维度（`●`）**：中性表示该维度已执行有效计算或合理估算。**覆盖不等于全部通过（PASS）**。
- **待补充后可评估（`○`）**：明确说明解锁完整平台规则或物理规则所需补充的信息（参数齐备时自动隐藏）。

## 5. 决策支持边界

UX Evaluation Tool 严格定位为设计前期的**决策支持工具**：
1. **早期暴露风险**：在设计图阶段发现触控拥挤、字号偏小及色彩对比不足。
2. **多参考系呈现**：呈现最低、推荐及最佳参考包络，而非单一武断的合成评分。
3. **非法律认证声明**：评估结果不替代正式的无障碍合规审计或车辆实际道路驾驶注意力分散测试。
