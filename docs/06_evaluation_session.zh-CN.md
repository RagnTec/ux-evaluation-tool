# 06 评估会话与工作区生命周期

[English](./06_evaluation_session.md) | **简体中文**

---

## 1. 概述与现代架构演进

在 **UX Evaluation Tool** 中，评估工作流围绕**响应式、持久化的工作区（Workspace）与本地项目（Local Project）生命周期**组织，而非仅作为一个短暂、静态的单次日志记录。

在早期原型阶段，系统曾将一次评估建模为扁平的一次性快照对象（`EvaluationSession`）。而在当前生产架构中，工作区演进为一个承载完整设计证据的状态容器：用户可以在画布上持续增量标注界面元素、调整显示硬件校准参数、更新视距，并即时获取重新计算的规则追溯链（Rule Trace）与呈现模型。

---

## 2. 核心实体与状态模型

```
┌────────────────────────────────────────────────────────────────────────┐
│ LocalProject (本地项目标识与仓库元数据)                                │
│ ├─ project_id, project_name, created_at, updated_at                    │
│ ├─ image_hash (SHA-256 哈希), image_name, image_width, image_height    │
│ └─ workspace: WorkspaceSerializedState (序列化工作区状态)              │
│     │                                                                  │
│     ├── 图像证据 (原始二进制 Blob、自然像素分辨率)                     │
│     ├── 硬件校准状态 (屏幕对角线英寸、物理分辨率、宽高比)              │
│     ├── 评估上下文 (视距、目标平台、设计单位基准)                      │
│     ├── 空间证据集合 (用户标注的 DesignElement 数组)                   │
│     └── 会话偏好设置 (评审员视角角色、评估模式)                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.1 项目标识（`LocalProject`, `ProjectSummary`）
- **`project_id`**：项目创建时生成的客户端唯一 UUID 标识符。
- **`project_name`**：用户自定义的项目名称，用于界面展示与报告导出归档。
- **`image_hash`**：源图像二进制的 SHA-256 加密摘要，用于同图自动识别、去重与项目历史关联。
- **`created_at` / `updated_at`**：记录本地项目创建与最后修改时间的 ISO-8601 时间戳。

### 2.2 工作区状态（`WorkspaceState`, `WorkspaceSerializedState`）
当前活跃评估会话的核心运行态：
- **图像证据**：原始图像二进制数据（`Blob`）及其固有像素尺寸（`image_width`, `image_height`）。
- **显示硬件校准状态**：屏幕对角线尺寸、物理分辨率、校准模式（全屏 `full_screen` vs 裁剪 `cropped`）以及计算得出的水平/垂直物理毫米每像素比例（`mmPerPixelX`, `mmPerPixelY`）。
- **上下文与设计基准**：目标操作系统平台（`iOS`, `Android`, `Web`, `Custom`）、设计逻辑参考基准（`pt`, `dp`, `CSS px` 或自定义参考宽度）及标称视距。
- **空间证据集合（`elements`）**：活跃的用户标注 `DesignElement` 数组，完整捕获元素可视包围盒、解耦的独立触控热区、代表字符测量范围及采样色彩对。
- **会话偏好**：当前评估模式（`quick`, `guided`, `precise`）与评审视角角色（`design`, `product`, `uxr`, `ops`）。

## 3. 生命周期流转与状态操作

### 3.1 项目创建与同图识别
1. 用户在工作区上传或拖入图片时，前端调用 Web Cryptography API（`crypto.subtle.digest`）计算其 **SHA-256 哈希值**。
2. 系统检索本地 IndexedDB，查找是否存在相同图像哈希的历史项目：
   - 若存在，提示用户可直接恢复已有工作区，或基于同图创建新的独立分支；
   - 若不存在，自动初始化全新的 `LocalProject` 实例，加载默认校准并初始化空白元素集。

### 3.2 动态重新计算与持久化边界
- **仅持久化源证据**：磁盘与数据库仅保存原始用户输入、空间标注证据及校准参数。
- **规则追溯链动态派生**：所有规则比对记录（`RuleComparisonTrace`）、视角弧分计算（θ = 2 arctan(h / 2D)）及呈现模型（`ElementPresentationModel`）均基于当前有效上下文**实时响应式重算**。
- 这一机制确保了当用户修改关键参数（如将视距从 400 mm 调整为 600 mm）时，所有标注元素的视角评估将立即同步更新，无需重新手动标注，彻底杜绝数据陈旧不一致。

### 3.3 自动保存与 IndexedDB 本地持久化
- 工作区状态变更经过防抖（debounce）后，自动序列化并写入浏览器的本地 **IndexedDB** 数据库（`ux_evaluation_workspace_db`，包含 workspace、projects 与 meta 对象仓库）。
- 图片二进制数据与工作区快照在页面刷新、标签页关闭或离线运行时均保持完整。

### 3.4 项目切换与状态还原
- **项目库（Project Library）**展示本地已保存的项目列表、元素数量、缩略图快照与修改时间。
- 切换项目时，当前工作区自动保存，清空画布图层，并将目标项目的数据结构反序列化载入内存工作区。

## 4. 明确的边界与非评估状态

### 4.1 UI 界面语言不是评估证据
- **语言偏好（`locale`）**：系统支持在英文（`en`）与简体中文（`zh-CN`）之间无刷新切换。
- **语义中立性**：语言切换仅属于界面呈现与词条本地化行为，**绝不改变**底层数值测量结果、规则判定、物理阈值或坐标数据。

### 4.2 演示模式与真实空间证据完全隔离
- **历史演示模块（`show_demo_results`）**：仅用于新用户快速浏览功能的预设静态模拟标注数据。
- **隔离保障**：演示数据通过独立的演示服务（`analysisService.ts`）提供，**绝不会**与用户实际手动测量的 `DesignElement` 空间证据混淆或保存入项目库。

### 4.3 评估成果定位与合规边界
- 保存的评估会话记录了特定时刻针对设计图所收集的空间证据与规则比对快照。
- 评估结果作为设计评审与研发交付过程中的**设计决策支持参考**，不构成法定或强制性合规认证背书。
