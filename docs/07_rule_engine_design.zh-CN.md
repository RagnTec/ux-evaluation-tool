# 07 规则引擎与评估架构设计

[English](./07_rule_engine_design.md) | **简体中文**

## 1. 引擎定位与确定性设计原则

**UX Evaluation Tool** 的评估引擎执行一套**确定性、多层级、由证据驱动的规则计算流水线**。

与启发式 AI 模型或主观打分算法不同，该引擎完全建立在数学物理推导与正式标准引用之上。每一项评估结论均源自用户核验的空间坐标、采样的色彩像素数据或校准的物理显示参数，最终生成可独立审查的规则比对追溯记录（`RuleComparisonTrace`）。

## 2. 多层规则体系架构与运行时范围

```
┌───────────────────────────────────────────────────────────┐
│ L5: 自定义规则层 (Custom Rules，架构预留扩展层)            │
├───────────────────────────────────────────────────────────┤
│ L4: 行业与领域规则 (Domain Rules，车载 HMI、桌面 Web、通用) │
├───────────────────────────────────────────────────────────┤
│ L3: 人因工程模型 (Human Factors，视距视角、9mm 触控等)     │
├───────────────────────────────────────────────────────────┤
│ L2: 平台官方规范 (Platform Guidelines，Apple HIG、Material)│
├───────────────────────────────────────────────────────────┤
│ L1: 底层硬性基准 (Hard Constraints，WCAG 2.2 AA、热区重叠) │
└───────────────────────────────────────────────────────────┘
```

### Public v0.1 层级运行状态：
- **L1–L3**：包含当前 Public 版本中直接开放的完整评估路径。
- **L4**：提供领域适用性控制与领域专项规则支持，其实际激活取决于当前可用的结构化场景条件。
- **L5**：在当前 Public 版本中仍属于架构扩展层（数据结构已完备定义，但规则录入与管理 UI 暂未开放）。

## 3. 核心概念边界与防误判原则

为确保评估结论的严谨性并避免误报，引擎严格执行以下五条概念边界：

### 3.1 目标平台 ≠ 设计单位基准
- **目标平台（Target Platform）**（如 `iOS`、`Android`、`Web`）：声明适用的操作系统生态与官方设计规范。
- **设计单位基准（Design Basis）**（如 `iPhone 15 Pro (393 pt)`、`Pixel 8 (412 dp)`、自定义参考宽度）：提供将渲染像素转换为逻辑单位（`pt`、`dp`、`CSS px`）的数学缩放比例。
- *执行规则*：若仅选择平台而未确认设计基准，平台规则（如 Apple 44 pt 触控）将输出 `needs_info`（待补充信息），但物理毫米计算与对比度评估完全不受影响、照常执行。

### 3.2 场景领域 ≠ 观察者角色 / 运行状态
- 选择**车载领域（`automotive`）**仅表明界面处于座舱显示环境中。
- 这**并不自动等同于**观察者为驾驶员、车辆处于行驶动态或当前任务具有时间紧迫性。
- *执行规则*：车载专项驾驶状态规则需要具体的结构化场景上下文支持。当前 Public 版本应用通用的座舱视距几何，且尚未在 UI 中开放全部驾驶角色与行车状态输入。

### 3.3 触控规则不可按视觉角度换算
- **生物力学事实**：物理触控交互取决于手指直接接触与肢体运动控制精度（对应通用手持直接触控参考 ≥ 9 mm）。
- *执行规则*：触控目标规则（如通用手持直接触控参考 ≥ 9 mm 或平台 48 dp 约束）**绝不能**换算为视网膜视角弧分（arcminutes）。视角换算仅适用于视觉清晰度识别与图形细节辨识。

### 3.4 测量目标语义兼容性门控
- 校验字号与字符可读性人因基准时，必须基于**代表性单字字符**（`character_height_px` / `character_cap_height`）的测量范围。
- *执行规则*：若标注框框选的是多行文本容器（`element_visual_bounds`），字符视角基准不会作为强制基准生效，从而防止容器高度虚高判定文字可读性。

### 3.5 注册基准 ≠ 强制法规
- 人因工程模型（如 ≥ 16′ 基本参考，≥ 20′ 推荐参考）属于经验工效学设计参考，非强制法律。
- 系统根据场景适用性将基准细分为基准底线（governing）、推荐基准（recommended）、最优参考（optimal）、次级参考（secondary）、适配参考（adapted）及描述性参考（descriptive）。

## 4. 评估流程与规则追溯链生成

```
[ 空间与色彩标注证据 ] ──► [ 能力与精度判定 (Precision Resolver) ]
                                         │
                                         ▼
[ 参考包络解析 (Envelope Resolver) ] ◄── [ 硬件校准与设计基准 ]
            │
            ▼
   [ 结构化数值比对 Formulation ] ──► [ 判定归纳与追溯链 Trace ]
                                         │
                                         ▼
                             [ ElementPresentationModel ]
```

### 4.1 步骤 1：证据与精度分级（Precision Tier）
针对每个 `DesignElement`，引擎判定当前可用的最高精度等级：
1. **Tier 1（截图事实）**：像素边界、面积占比、采样色彩对比度。
2. **Tier 2（硬件假定）**：基于屏幕对角线与分辨率校准的物理毫米（mm）尺寸。
3. **Tier 3（设计映射）**：基于设计参考宽度的逻辑单位（`pt` / `dp` / `CSS px`）尺寸。
4. **Tier 4（设计源确认）**：源文件确认的字号字重或明确划分的独立触控热区。

### 4.2 步骤 2：参考包络解析（`resolveReferenceEnvelope`）
候选规则依据以下条件进行过滤与门控：
- **测量目标检查**：校验测量对象类型（如单字高度 vs 元素可视包围盒）。
- **场景范围匹配**：校验观察者角色、运行状态及环境适用性。
- **参考角色分配**：确定基准底线、推荐值或保守参考角色。

### 4.3 步骤 3：结构化数值比对（`ComparisonDetails`）
比对详情被组织为类型化的数学载荷：
- `scalar_min`：标量最小值检测（如对比度 ≥ 4.5:1、物理触控 ≥ 9.0 mm）。
- `scalar_max`：标量最大值检测。
- `range`：区间范围检测（如视角推荐区间）。
- `multi_axis`：双轴尺寸评估（包含宽度与高度比对及限制轴标记）。
- `conditional`：多条件依赖判定。
- `needs_info`：明确列出解锁评估所需的缺失参数。
- `measurement_only`：在无规范阈值时输出客观测量值。

### 4.4 步骤 4：追溯判定分配（`TraceVerdict`）
每项检测输出明确的判定结论：
- `meets`：达到推荐范围。
- `below_recommended`：满足基本要求，但未达推荐范围。
- `attention`：低于基本要求或基准底线，需设计关注。
- `estimated_meets` / `estimated_below_recommended` / `estimated_attention`：基于单行排版估算得出的结论。
- `measurement_only`：仅测量记录，不作合规判定。
- `needs_info`：缺少必要校准或设计基准信息。
- `not_applicable`：规则对当前元素类型或平台不适用。

## 5. 优先级与冲突处理边界

1. **L1 硬性基准绝对优先**：WCAG 2.2 AA 无障碍底线与热区重叠冲突具有最高优先级，平台规范（L2）或自定义规则（L5）不可静默覆盖 L1 缺陷。
2. **认识论归因清晰**：追溯链显式携带推理来源：
   - `rule_match`：命中已核验的标准或平台规范。
   - `theory_inference`：人因工效理论推导。
   - `heuristic_risk`：启发式估算风险。
   - `domain_adapted`：领域适配门控基准。
3. **正交非阻塞机制**：某一维度缺失输入（如缺少设计基准导致 L2 无法计算）仅在该项输出 `needs_info`，绝不阻塞物理尺寸（L3）或对比度（L1）的正常计算。
